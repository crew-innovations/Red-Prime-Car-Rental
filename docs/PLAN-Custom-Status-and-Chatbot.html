Part A — Custom status

What it is

Staff need a label of their own, such as “VIP follow-up” or “Airport run”, on a lead, a booking, or a quotation. The pipeline stage, the booking status, and the quotation status stay exactly as they are. The label does not confirm a car, collect money, or move a lead to Won or Lost.

Who can do what

PersonCan
AdminAdd a new label, pick one, or clear it.
Anyone who can open the recordPick a label that already exists for that record type, or clear it.
Sales and other staffCannot type a new label. The box is hidden, and the server rejects it if it is sent anyway.

A label saved on a lead is offered only on leads. A booking label is offered only on bookings. A quotation label is offered only on quotations.

Data

One new table, custom_statuses: name (max 80 characters), colour (grey, blue, green, amber, red, brand), record type (lead, booking, or quotation), active flag, who created it. Unique on record type plus name.

One new nullable column, custom_status_id, on leads, bookings, and quotations. Existing rows stay empty. The migration only adds these. down() drops only these. No old status column is changed or removed.

Screens

  • Lead, booking, and quotation edit pages: a Custom status button beside the main action (with WhatsApp and Call, not buried only under More).
  • The same action inside the row menu on each list.
  • A Custom status column on each list. Empty until a label is chosen.
  • The page heading line shows the label after the real status.
  • Help text on Leads, Quotations, and Bookings: one sentence that this label does not change the stage or the booking status.

Cars, yachts, payments, documents, contracts, and driver jobs are out of this part. Their statuses drive availability, money, and handover.

Files

  • New: database/migrations/2026_11_27_000001_custom_statuses.php, app/Models/CustomStatus.php, app/Support/CustomStatuses.php, app/Filament/Support/CustomStatusAction.php, tests/Feature/CustomStatusTest.php.
  • Edit: Lead, Booking, and Quotation models and resources, their edit pages, HasNextStep, and HelpGuides.

Tests that must pass

  1. Admin adds “VIP follow-up” on a lead. The pipeline stage and lead status stay the same. The label is stored.
  2. A salesperson picks that style of label on a booking. The booking status stays Confirmed (or whatever it was). The salesperson cannot create a new name: the server returns 403.
  3. A booking label cannot be saved on a quotation.

Done when

The three tests pass. Leads, Bookings, and Quotations open. A record with no label looks as it does today. Pay now / Pay later on the website is left as it is.

Part B — Website chatbot

What it is

A chat box on the public website. The visitor asks about the fleet and how to book. The server answers from data the website is already allowed to show, in the language the visitor is using (English or Arabic).

CRM Messages stays as it is. That screen is for staff, customers, and drivers inside an account. The website bot is a new public conversation. It does not write into staff chat threads.

What the bot is allowed to know

Only the public catalogue, through the code that already builds it (FleetResource and the catalogue routes). For a car that means name, brand, model, year, body, transmission, fuel, seats, doors, luggage, colour, horsepower, self-drive or with driver, the public prices, the deposit shown on the site, rental rules, features, and description. The same idea applies to published yachts, trips, and packages.

For a date question, the server calls the existing price estimate (POST /api/v1/price-estimate). That uses the same price engine as the CRM and does not book or hold anything. The reply the customer sees is the estimate total and whether the dates can be requested. The security deposit stays a separate line, as it does on Book now. It is not added into the total.

The bot may explain the flow that is already built:

QuestionPrice, car, dates, how booking works.
EnquiryName and phone only. A lead. Nothing is booked.
Book nowCreates a booking waiting for payment.
Pay now or laterOnly if a payment gateway is connected. The link is the booking total.
After paymentThe screen reads Paid, documents pending until staff confirm.

What the bot must not see or do

  • Other customers’ names, phones, documents, bookings, or staff notes.
  • Registration, VIN, insurance files, partner rates, commission, supplier cost, or internal car status notes. Those are already excluded from FleetResource.
  • It must not confirm a booking, mark a payment, change a deposit, or invent a price, a fee, a document rule, or a cancellation rule. If the database does not contain the answer, it says the team will confirm and offers the enquiry.
  • A limousine whose price the agent must still confirm is explained as a request. The bot does not offer Pay now on it.

How a message is handled

  1. The browser sends the message to POST /api/v1/chat. The AI key never goes to the browser.
  2. The server checks a short-lived visitor token (a random id in the browser, not a customer password). One visitor is limited, the same style of limit as the booking form, so the AI bill cannot run away.
  3. The server decides which tool to use, then calls only that tool:
    • Fleet search: published cars (and yachts, trips, packages) matching the question.
    • Price estimate: when the visitor names a car and dates.
    • Create booking: only when the visitor has agreed, and the same fields Book now already requires are present (car, dates, drive mode, name, phone, email). This calls the existing BookingRequestController. Pay now redirects to the pay link when they choose it and a gateway is connected. Pay later emails the link.
    • Create enquiry: when they want a person to call, or the bot cannot answer. This calls the existing enquiry route. A lead appears in Leads. No booking is created.
  4. The model writes the reply from the tool result only. The server stores the question, the reply, and which tool was used. Staff can open that log later. It is not a CRM Message thread.

Where it appears

First: home page and car pages, English and Arabic. A button opens the box. The car page already knows which car is open, so the first message can include that car. Yacht, trip, package, and limousine pages are the next slice, after the car path is tested. The box uses the site font and the red button. No new visual system.

AI account

Use the same kind of key as Settings › Integrations › Document reader: Anthropic or OpenAI, key stored as a secret, switched on by an Admin, Test connection before it is used. A separate card named Website assistant is clearer than reusing the document-reader key, because the document reader sends ID images and this assistant must not. Billing on that AI account is required. RED PRIME chooses the provider before this part starts.

Tests that must pass

  1. Ask the daily price of a published car. The answer matches the catalogue price.
  2. Ask for dates that are already blocked. The answer does not claim the car is free.
  3. Ask something the database does not contain (a made-up fee). The answer does not invent a number and offers an enquiry.
  4. Complete Book now from the chat. One booking, status Waiting for payment, lead on Payment Pending, no second “send a quotation” alert.
  5. With no payment gateway connected, the chat does not offer Pay now.
  6. The request refuses to load another customer’s phone or booking, even if the question asks for it.

Done when

B1–B4 are checked on the car pages in a browser, in English and Arabic. The help guide for the website and for Leads says a chat booking is the same as Book now. The AI key is in Integrations and is not written into the page or into git.
