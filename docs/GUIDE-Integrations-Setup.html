How to set up every API in Integrations

RED PRIME RENTALS CRM. Open this on the office computer. Do the cards in this order. Test mode first. Live mode charges real money.

Before you start

  1. Sign in to the CRM as an Admin: https://redprimerentals.com/crm
  2. Open Settings › Integrations. Only an Admin can save keys.
  3. On every card the order is the same: fill the fields, switch it On, press Save, then press Test connection.
  4. A secret field that says Saved · leave empty to keep already has a key. Leave it blank unless you are replacing it. Typing nothing does not wipe the old key.
  5. Payment cards have Test / sandbox and Live. Those are two separate stores. A test key will not work while the card is set to Live, and the other way round.
  6. Saving a new key sets the card to Details saved, not tested. It is not in use until Test connection says it is connected. Payments only appear on the website after that.
  7. Where a card shows Webhook address, copy that address into the other company’s website. Do not invent one. If the address starts with localhost, stop: the CRM site address is wrong and outside companies cannot reach it. The live addresses are listed under each card below.
As last checked on 26 November 2026, no card was Connected. Google Maps was On and showing “Save the server key first.” Stripe, Paymob and Tamara were On in Test with keys missing. Tabby, PayPal, messages and the document reader were not set up. Facebook Lead Ads was On with secrets missing. TikTok and Snapchat were On with the shared secret missing.

1. Google Maps

Used for limousine distance and time, address search, and the route map. The CRM works as soon as the card is On and the server key is saved. Test connection is still required, because a bad key only shows up when a route is asked for.

In Google Cloud (use the company Google account)

  1. Open https://console.cloud.google.com and create a project named for RED PRIME. Do not reuse a personal project.
  2. Link a billing account to that project. Routes and Places refuse the key until billing is on. Do not type a card into a personal project.
  3. APIs & Services › Library. Enable these five, one by one: Routes API, Places API (New), Geocoding API, Maps Embed API, Maps JavaScript API.
  4. APIs & Services › Credentials › Create credentials › API key. This is the server key.
    • Application restriction: IP addresses. Add the Hostinger server’s outbound IP. The CRM calls Google from the server, so a browser-only restriction will fail.
    • API restriction: Routes API, Places API (New), Geocoding API.
  5. Create a second key. This is the browser key.
    • Application restriction: HTTP referrers. Add https://redprimerentals.com/*, https://www.redprimerentals.com/* and https://crm.redprimerentals.com/*.
    • API restriction: Maps Embed API and Maps JavaScript API.

In the CRM

  1. Google Maps card. Switch On. Country code: ae.
  2. Paste the server key. Paste the browser key. Save. Test connection.
Success reads: Routes API working (a number of km, test route). The test drives Dubai Mall to Dubai International Airport Terminal 3. It does not test the browser key, Places, Geocoding, or the map on the page. If the browser key is missing, the same success line ends with no browser key: map preview off.
If the test says thisWhat to do
Save the server key first.The server key box was empty. Paste it and Save, then test again.
API key not valid.The key is wrong, deleted, or the IP restriction does not include the Hostinger server.
Routes API … is disabled / has not been used.Enable Routes API on that same project, and confirm billing is on. Wait a minute and test again.
Google Maps did not answer.The server could not reach Google. Try again. If it stays, the server’s outbound internet is blocked.

2. Stripe

Card, Apple Pay and Google Pay. The website button will say Pay by card / Apple Pay.

  1. Open the Stripe Dashboard for the company. Keep the mode switch on Test.
  2. Developers › API keys. Copy the Secret key that starts with sk_test_. Do not use the publishable key.
  3. Developers › Webhooks › Add endpoint. Address: https://redprimerentals.com/api/webhooks/payments/stripe
  4. Select these events only: checkout.session.completed, checkout.session.async_payment_succeeded, checkout.session.async_payment_failed, checkout.session.expired.
  5. Open the endpoint and reveal the Signing secret. It starts with whsec_.
  6. CRM card: switch On, Mode Test / sandbox, paste both secrets, Save, Test connection.
Success reads: Stripe · test mode.
If the test says thisWhat to do
Secret key not savedPaste the secret key and Save before testing.
This is a live key but the mode is set to test. (or the reverse)The key and the Mode switch do not match. Use sk_test_ with Test, sk_live_ with Live.
API key works. Add the webhook signing secret so payments can be confirmed.Paste the whsec_ value and Save, then test again. Without it, a payment is not recorded.
Could not reach StripeThe server could not open Stripe. Try again.
A sentence from Stripe, such as Invalid API KeyThe secret key is wrong or revoked. Copy it again from the same mode.

When a real charge is wanted: in Stripe switch to Live, create a separate live webhook to the same address, copy sk_live_ and the live whsec_. In the CRM set Mode to Live, paste those, Save, Test. Success reads Stripe · live.

3. Paymob

Cards and UAE wallets. The website button will say Pay by card (Paymob). Use the UAE dashboard, normally https://uae.paymob.com.

  1. Stay in Paymob’s test environment first.
  2. Settings › Account info. Copy four values: API key, Secret key, Public key, HMAC secret.
  3. Developers › Payment integrations. Copy each integration ID you want to offer (card, Apple Pay, and so on). Test IDs and live IDs are different.
  4. On each of those integrations, set the transaction processed callback to https://redprimerentals.com/api/webhooks/payments/paymob
  5. CRM card: switch On, Mode Test. API address stays https://uae.paymob.com. Integration ID(s): the numbers, separated by commas. Paste the four secrets. Save. Test connection.
Success reads: Paymob · the company name · test.
If the test says thisWhat to do
API key not saved / Secret key not saved / Public key not saved / HMAC secret not savedThat box was empty. Paste it and Save.
Add the integration ID(s)…The Integration ID field is empty.
The secret key does not look like a test key.A test secret contains sk_test. A live secret contains sk_live. Match the Mode switch.
API key refused (HTTP …)The API key was rejected. Copy it again from Account info in the same environment.
Could not reach PaymobCheck the API address is https://uae.paymob.com and try again.

4. Tabby

Split in 4. The button says Split in 4 with Tabby. Tabby must approve the business before live checkout works. The CRM never shows Tabby’s reason when a customer is declined; the button is simply not offered for that payment.

  1. From Tabby, take the test public key (pk_), secret key (sk_), and the merchant code for AED.
  2. Choose a long random text. This is the webhook header value. In the CRM the header name defaults to X-RP-Webhook. Keep that name unless Tabby gave you a different header name.
  3. In Tabby, register a webhook (their docs: POST /api/v1/webhooks) to https://redprimerentals.com/api/webhooks/payments/tabby and send that header name with the random value.
  4. CRM card: switch On, Mode Test, merchant code, header name, the three secrets. Optional: smallest and largest amount in AED, only if Tabby agreed a limit. Save. Test connection.
Success reads: Tabby · merchant code · test. The test only passes when Tabby’s webhook list already contains the CRM address.
If the test says thisWhat to do
Public key not saved / Secret key not saved / Webhook header value not savedPaste that secret and Save.
Merchant code not setType the code Tabby gave you.
Secret key refused (HTTP …)Wrong secret, or it does not belong to that merchant code.
Keys work, but the CRM webhook is not registered with Tabby yet…Register the webhook in Tabby, then test again. Keys alone are not enough.

  3. Point Tamara notifications at https://redprimerentals.com/api/webhooks/payments/tamara
  4. CRM card: switch On, Mode Test, paste both tokens. Save. Test connection.
Success reads: Tamara · sandbox. Live mode success reads Tamara · live.
If the test says thisWhat to do

Notification token not savedPaste the notification token and Save. Without it, a paid order is not confirmed.

6. PayPal

The button says Pay with PayPal. PayPal does not take AED. You choose USD, EUR or GBP and the AED rate. The CRM converts the booking amount with that rate.

  1. PayPal Developer › Apps. Open the sandbox app first.
  2. Copy Client ID and Secret.
  3. Add a webhook on that app. Address: https://redprimerentals.com/api/webhooks/payments/paypal. Event: PAYMENT.CAPTURE.COMPLETED. Also add PAYMENT.CAPTURE.DECLINED and PAYMENT.CAPTURE.DENIED if PayPal offers them. Copy the Webhook ID.
  4. CRM card: switch On, Mode Test. Currency, for example USD. AED per 1 unit, for example 3.6725 for USD (you decide the rate; the CRM does not look one up). Webhook ID. Client ID and secret. Save. Test connection.
Success reads: PayPal · sandbox · USD (or the currency you set). The test only checks the client ID and secret. It does not check the webhook.
If the test says thisWhat to do
Client ID and secret not savedPaste both and Save.
PayPal does not take AED: set the PayPal currency and the AED rate first.Currency and a rate above zero are required before the test will call PayPal.
A PayPal error, or Could not reach PayPalThe ID and secret do not match this mode, or PayPal did not answer.

If the Webhook ID box is empty, a PayPal notice arrives and is rejected with Webhook ID not set. The customer can still return from PayPal and the return page can record the payment, but the notice itself will not.

7. Facebook and Instagram Lead Ads

A lead form on Facebook or Instagram becomes a CRM lead. The card must be On and saved before Meta checks the address. If Meta checks first, the event log says Verify token did not match.

  1. In Meta for Developers, use a Business app. Add the Webhooks product.
  2. App settings › Basic. Copy the App secret.
  3. Make a long random text. That is the verify token. You will type the same text in Meta.
  4. Create a long-lived Page access token for the Facebook Page that owns the lead forms. The token needs leads_retrieval, pages_manage_metadata, pages_show_list, pages_read_engagement. Meta must approve leads_retrieval in App Review before live lead forms work.
  5. Copy the Facebook Page ID.
  6. CRM card: switch On. Page ID. Graph API version v21.0 unless Meta tells you a newer one. Service: leave empty unless every lead from this Page is the same service. Paste app secret, page token and verify token. Save.
  7. In Meta: Webhooks › Page › subscribe to leadgen. Callback URL: https://redprimerentals.com/api/webhooks/leads/meta. Verify token: the same text you saved. Press Verify and save.
  8. Subscribe the app to the Page, and in the Page settings give the CRM access to leads.
  9. Back in the CRM, Test connection.
Success reads: Page: the Page name (Page ID).
If the test says thisWhat to do
App secret not saved / Page access token not saved / Verify token not savedPaste that value and Save.
The token belongs to “…”, not the Page ID you set.The token is for a different Page. Fix the Page ID or generate the token on the right Page.
A Meta error, such as Invalid OAuth access tokenThe page token is expired or missing a permission. Generate it again.
In the event list: Verify token did not matchMeta’s verify token and the saved one differ, or the card was Off when Meta checked. Save, switch On, then verify again in Meta.
In the event list: Not set up or switched offA lead arrived while the card was Off or a required secret was missing.

8. TikTok Lead Generation

Test connection does not call TikTok. It only looks for a lead that already arrived with a valid signature. Until that happens, the test fails even when the secret is correct.

  1. TikTok for Business, with Lead Generation and webhook access.
  2. Choose a long random shared secret.
  3. CRM card: switch On. Signature header stays X-TikTok-Signature unless TikTok’s form uses another header name. Paste the shared secret. Save.
  4. In TikTok, set the webhook to https://redprimerentals.com/api/webhooks/leads/tiktok. TikTok must sign the raw body with HMAC-SHA256 using that secret. The header may be the hex digest or sha256= plus the digest. The CRM accepts both.
  5. Send one real test lead from TikTok. Open the card’s recent events. A good lead is direction in, status ok.
  6. Press Test connection.
Success reads: TikTok Lead Generation · last lead received and the date.
If you see thisWhat it means
Shared secret not savedPaste the secret and Save before testing.
No signed test lead received yet…Expected until TikTok has delivered one lead the CRM accepted. Send the test lead, then test again.
HTTP 404, event “Not set up or switched off”The card was Off or the secret was empty when TikTok called.
HTTP 400, the signature header does not matchThe secret in TikTok and the secret in the CRM are different, or TikTok signed a different body.

The lead body must include lead_id or id, plus a name and a phone or email. If TikTok’s real payload uses other field names, the lead can be rejected even with a correct signature. That is why one test lead is checked before the card is treated as working.

9. Snapchat Lead Generation

Same rule as TikTok. The test looks for a past accepted lead. It does not call Snapchat.

  1. Snapchat Ads, with Lead Generation and Marketing API access.
  2. Choose a long random shared secret.
  3. CRM card: switch On. Signature header stays X-Snap-Signature. Paste the secret. Save.
  4. In Snapchat, set the webhook to https://redprimerentals.com/api/webhooks/leads/snapchat and sign the raw body with HMAC-SHA256.
  5. Send one test lead. Confirm an event with status ok. Then Test connection.
Success reads: Snapchat Lead Generation · last lead received and the date. The failure sentences are the same as TikTok, with the Snapchat header name.

10. Instagram, Facebook and WhatsApp messages

A customer message becomes a lead, and the reply goes back on the same channel. This is a different card from Lead Ads, with its own verify token. On 26 November 2026 the event log already had five failures: Verify token did not match. That means Meta checked this address and the token did not match what is saved (or nothing was saved).

  1. Instagram professional account linked to the Facebook Page, with “Allow access to messages” on.
  2. Meta app, Business type, with Messenger and Instagram. Add WhatsApp only if you will use it. App Review must approve instagram_manage_messages and pages_messaging. The business must be verified.
  3. App settings › Basic: copy the App secret. Make a new long verify token (it can differ from the Lead Ads token).
  4. For Instagram and Messenger replies: a long-lived Page access token with instagram_manage_messages, pages_messaging, pages_manage_metadata.
  5. For WhatsApp: WhatsApp Manager › API setup. Copy the phone number ID. Create a permanent system-user token with whatsapp_business_messaging. Meta charges per WhatsApp conversation.
  6. Optional WhatsApp templates, already approved in Meta: contract (three values: name, contract number, link), invoice (name, invoice number and amount, link), and the language code such as en.
  7. CRM card: switch On. Fill the WhatsApp phone number ID if you use WhatsApp. Graph version v21.0. Paste app secret and verify token, plus the page token and/or the WhatsApp token. Save.
  8. In Meta, subscribe messages for Instagram, the Page, and (if used) the WhatsApp Business Account. Callback: https://redprimerentals.com/api/webhooks/messages/meta. Verify token: the one just saved. Verify only after Save.
  9. Test connection.
Success reads Page: the Page name, and if WhatsApp is set, WhatsApp: the phone number.
If the test says thisWhat to do
App secret not saved / Verify token not savedPaste it and Save. The card cannot receive messages without both.
Save the Page access token (Instagram / Messenger) or the WhatsApp token…At least one reply token is required. The test will not pass on the app secret alone.
WhatsApp phone number ID not setYou pasted a WhatsApp token. Also fill the phone number ID.
Page token: … / WhatsApp: …Meta rejected that token. The rest of the sentence is Meta’s reason.

11. Document reader

Reads an Emirates ID, passport, driving licence, visa, trade licence or receipt and fills the form. Staff still check the fields before saving. The image is sent to Anthropic or OpenAI. Do not switch this on until RED PRIME agrees to that.

  1. Create an API key in the Anthropic console or the OpenAI console, on an account with billing.
  2. CRM card: switch On. Service: Anthropic (Claude) or OpenAI (GPT). Model: leave empty to use the default (Anthropic claude-haiku-5-5, OpenAI gpt-4o-mini), or type the model name the account is allowed to use. Paste the API key. Save. Test connection.
Success reads: The document reader answered. The test sends the sentence “Reply with the JSON object {“ok”: true}” and looks for the word true. It does not upload an ID.
If the test says thisWhat to do
Save the API key first.The key box was empty.
Unexpected answer: …The service replied, but the reply did not contain “true”. Try again, or set the model the account can use.
Any other sentenceThat sentence is the service’s error: wrong key, no billing, or a model name it does not have.

After a payment card is connected

On the website Book now form (car, yacht, trip, package), the customer sees Pay now and Pay later. Pay later is already selected.

  • Pay later. The booking is saved as Waiting for payment. The same email that confirms the booking contains the pay link (/pay/…).
  • Pay now. The same booking and the same email are created, and the browser opens that pay page. The customer picks whichever connected gateway is on the page.
  • The link asks for the booking total they were shown. It does not charge the security deposit. The deposit stays a separate line for the office.
  • When the gateway confirms the exact amount, the booking’s payment becomes Paid. On the booking screen the status line reads Paid, documents pending. The stored booking status stays Waiting for payment until staff confirm it, because a car still needs its documents when that rule is on. There is no separate status called Paid.
  • A limousine request whose price the agent must still confirm does not show Pay now / Pay later, and no link is emailed. The customer gets the ride page after the agent sets the price.
  • If no gateway is connected, the form does not show the choice. The email says the team will send the payment link, which is the old behaviour.

Disconnect on a card deletes its saved keys and switches it off. Leads and payments already stored stay.
